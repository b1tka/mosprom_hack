# Онбординг-бот для MAX

Бот для мессенджера [MAX](https://max.ru): помогает новому сотруднику войти в компанию. Ведёт его по сценарию онбординга, отвечает на вопросы по базе знаний и связывает с HR.

## Что умеет

- **Добавление сотрудника.** HR в `/menu` вводит данные (или присылает PDF — ML достаёт поля сам) и получает QR. Сотрудник сканирует QR и подтверждает свой контакт.
- **Сценарий онбординга** по ТЗ: шаги по расписанию, ответы сотрудника, напоминания, письма (`bot/src/scenario/scenario.yaml`).
- **Ответы на вопросы (RAG).** Поиск по базе знаний + LLM. Если ответа нет — предложение передать вопрос HR.
- **Обращения к HR.** Тикеты сотрудник ↔ закреплённый HR с перепиской, архивом и вложениями.
- **База знаний.** HR добавляет и удаляет документы прямо из бота.
- **Настроение сотрудников.** ML оценивает ответы и диалоги; при тревожных сигналах (red flag) HR получает уведомление. Отчёты уходят на почту (`hr_analytics/`).
- **Тестовая админка** (`admin/`) — только для тестирования.

## Архитектура

| Компонент | Назначение |
|---|---|
| `bot/` | Бот на JS (`@maxhub/max-bot-api`) |
| `ml/` | FastAPI: RAG (Chroma + e5-large), LLM в Ollama, оценка настроения |
| `hr_analytics/` | Отчёты HR на почту |
| `admin/` | Тестовая админка (FastAPI + HTMX) |
| Postgres | Пользователи, роли, теги, приглашения |
| MongoDB | Тикеты, статистика настроения |
| Redis | Состояние диалогов |
| S3 (OpenMaxIO) | Файлы и документы базы знаний |
| Kafka | Ответы и диалоги -> ML, red flag -> бот |

Роли: `employee`, `director`, `hr`, `hr_head`. Теги сотрудника: GTP, GrPP, Luzhniki.

## Быстрый старт

Полная пошаговая инструкция воспроизведения решения (первый HR, база знаний, демо-сценарий, прохождение онбординга через админку) — в [`PIPELINE.md`](PIPELINE.md). Ниже — краткая версия.

```bash
cp .env.example .env              # поменять пароли, указать BOT_TOKEN
docker compose --profile llm up -d   # сразу с LLM, нужно >= 12 ГБ RAM
docker compose ps -a
docker compose logs bot
```

Без LLM (слабая машина): `docker compose up -d` — бот работает, но `/v1/ask` отдаёт 503.

После правок кода: `docker compose up -d --build bot` (или `ml ml-mood-consumer`).
Миграции из `db/migrations/` применяются к живой БД вручную **до** пересборки бота.
