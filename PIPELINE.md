# PIPELINE: как воспроизвести решение

Пошаговая инструкция: от чистой машины до работающего бота и проверки всех сценариев. Описание архитектуры — в `INFRASTRUCTURE.md`.

## 0. Что нужно

- Linux-сервер или ПК с **Docker + Docker Compose**, доступ в интернет (образы, модели, MAX API).
- **≥ 12 ГБ RAM для Docker** (лучше 16) — с LLM; ~25 ГБ диска (образы, модель эмбеддингов 2.2 ГБ, LLM 4.7 ГБ).
- Бот в MAX: токен из https://dev.max.ru (раздел чат-ботов).
- Свой аккаунт в MAX и (для проверки роли сотрудника) второй аккаунт / второй человек.
- Необязательно: ящик Яндекса с паролем приложения (письма и отчёты).

## 1. Настройка

```bash
git clone <репозиторий> && cd mosprom_hack
cp .env.example .env
```

В `.env` заполнить:
- `BOT_TOKEN` — токен бота;
- заменить пароли-заглушки: `POSTGRES_PASSWORD`, `S3_ROOT_PASSWORD`, `MONGO_ROOT_PASSWORD`, `MONGO_APP_PASSWORD`;
- для тестовой админки: `ADMIN_ACCESS=anyone` (или `hr`), `ADMIN_API_TOKEN` и `SESSION_SECRET` — случайные строки (`openssl rand -hex 32`);
- `SMTP_USER` / `SMTP_PASSWORD` — только если нужны письма (приветственное письмо сотруднику, отчёты); без них эти шаги пропускаются.

## 2. Запуск стека

```bash
docker compose --profile llm --profile admin up -d --build
docker compose ps -a
```

Что произойдёт при первом старте:
- Postgres, MongoDB, S3, Kafka создадут схемы, пользователей, бакет и топики автоматически (`db/init/`, `db/mongo-init/`, `s3-init`, `kafka-init`);
- `ollama-init` скачает LLM, `ml` — модель эмбеддингов e5-large (~2.2 ГБ). На медленной сети это до ~40 минут, пока `ml` может быть `unhealthy` — это не ошибка;
- `docker compose logs -f ollama-init ml` показывает ход загрузки.

Если контейнер `mongo` или `ml-mood-consumer` остался в `Exited` (Docker перезапускался) — `docker compose up -d`.

## 3. Первый HR-пользователь

Бот сам создаёт только сотрудников. HR заводится вручную. Свой `max_id` узнать, написав боту `/id`, затем в интерактивном `psql`:

```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```
```sql
INSERT INTO users (name, surname, role_id, max_id)
SELECT 'Имя', 'Фамилия', id, <ВАШ_MAX_ID> FROM role WHERE name = 'hr'
ON CONFLICT (max_id) DO UPDATE SET role_id = EXCLUDED.role_id;
```

(Для видимости отчётов у HR, директоров заполняется `email`: `UPDATE users SET email = '…' WHERE max_id = …`.)

Для демонстрации нужен ещё руководитель подразделения (`role = 'director'`) — сотрудник привязывается к нему при добавлении. Заводится тем же `INSERT` с ролью `director`.

> Миграции `db/migrations/` нужны только для БД, созданной **до** них. На чистой установке схема уже актуальна (`db/init/`).

## 4. База знаний

Без документов ответы на вопросы сотрудников не работают (`/v1/ask` вернёт 503 «Векторная база пуста»).

Вариант А — через бота: HR → `/menu` → «База знаний» → «Добавить файл» (PDF, TXT, MD до 50 МБ). Индексация идёт в фоне, бот пришлёт уведомление.

Вариант Б — пакетно через CLI (PDF стартового набора лежат в ветке `mood_find`):

```bash
git archive origin/mood_find data | tar -x
docker compose run --rm -v "$PWD/data":/import ml python -m app.ingest upload /import
docker compose stop ml
docker compose run --rm ml python -m app.ingest build --from-s3     # ~11 минут на CPU (OCR сканов)
docker compose up -d ml
```

## 5. Проверка работоспособности

```bash
./scripts/smoke.sh            # --no-llm без проверок модели, --keep не удалять тестовые данные
```

Скрипт проверяет контейнеры, схему БД, Redis/Kafka/S3, ML API, а с LLM — ответы `/v1/ask`, запись оценки настроения и путь «диалог тикета → Kafka → консьюмер → Mongo». `FAIL` — стек неисправен, `WARN` — на что обратить внимание.

## 6. Сквозной сценарий (демонстрация)

### 6.1. Добавить сотрудника
1. HR пишет боту `/menu` → «Добавить нового сотрудника» (или присылает PDF-анкету → бот извлечёт данные сам).
2. Ввести имя, фамилию, выбрать тег (GTP / GrPP / Luzhniki) и руководителя, указать почту и телефон, подтвердить.
3. Бот пришлёт QR-код и ссылку `https://max.ru/<бот>?start=<токен>` (7 дней, одноразовая).
4. Сотрудник (второй аккаунт) открывает ссылку и нажимает «Поделиться контактом». Номер должен принадлежать ему и совпадать с введённым HR. Появляется запись `employee`, HR получает уведомление, **запускается сценарий онбординга**.

### 6.2. Сценарий онбординга
Сценарий (`bot/src/scenario/scenario.yaml`) идёт по расписанию от даты выхода: знакомство до выхода, первый день по часам, 3-й день, 2 недели, 2 месяца, окончание испытательного срока. Ждать месяцы не нужно — используйте тестовую админку (шаг 7).

### 6.3. Вопрос боту (RAG)
Сотрудник пишет вопрос обычным текстом (например, «сколько дней отпуска?»). Бот отвечает по базе знаний; под ответом кнопка «Связаться с HR». Если ответа в базе нет — бот предлагает «Передать вопрос в отдел подбора персонала».

### 6.4. Обращение к HR
Сотрудник жмёт «Связаться с HR» → открывается тикет и чат. HR получает уведомление, отвечает через `/menu` → «Обращения»; закрыть может любая сторона. Закрытый диалог уходит на оценку настроения.

### 6.5. Красный флаг
Сотрудник пишет эмоционально негативный/срочный текст (в вопросе, в опросе или в тикете) → ML помечает срочность → закреплённому HR приходит алерт с кнопками «Открыть обращение» и «Флаг обработан» (не чаще раза в час на сотрудника).

### 6.6. Отчёты (необязательно)
Нужен SMTP. `./scripts/seed_demo.sh demo` собирает письма на демо-данных без записи в базы; для реальных данных:
```bash
docker compose --profile reports run --rm hr-analytics python -m app check
docker compose --profile reports run --rm hr-analytics python -m app preview     # HTML+PDF без отправки
```
Пока задан `REPORT_RECIPIENT_OVERRIDE`, все письма уходят на один адрес с пометкой `[TEST]`.

## 7. Как воспроизвести конкретный случай сотрудника (админка)

Тестовая админка позволяет пройти сценарий за минуты и повторить любую ветку.

1. Доступ: `ssh -L 8080:localhost:8080 <сервер>` → http://localhost:8080 (порт слушает только `127.0.0.1`).
2. Вход: написать боту `/admin`, ввести 8-значный код (действует 5 минут, одноразовый) или открыть ссылку из сообщения.
3. Раздел **«Онбординг»** → выбрать сотрудника. Если сценарий не запущен — «Запустить сценарий» (при необходимости указать дату выхода).
4. Управление:
   | Действие | Что делает |
   |----------|-----------|
   | **▶ Выполнить** у любого шага | отправить сотруднику именно этот шаг сейчас, с начала; ответы и ожидания шага сбрасываются — можно проходить ветки повторно и в любом порядке |
   | Выполнить следующий шаг сейчас | ближайший по расписанию шаг |
   | Сдвинуть будущие шаги на N дн. | отрицательное число приближает шаги |
   | Дата выхода → «Пересчитать» | пересчитывает всё расписание |
   | Пауза / Продолжить | останавливает автоматическую отправку |
   | Удалить онбординг и ответы | полный сброс, после него можно запустить заново (требует слова `ПОДТВЕРЖДАЮ`) |
5. Как повторить ветку: нажать «▶ Выполнить» у шага с вопросом → ответить кнопками в MAX (ответы бота видны в таблице «Ответы на вопросы и опросы») → при необходимости нажать «▶ Выполнить» у того же шага и выбрать другой ответ.
   Негативный ответ (шкала ниже 8, «Нет» по доступам и т. п.) сразу уходит закреплённому HR и в оценку настроения.
6. Остальные разделы админки: сотрудники и настроение, тикеты (ответить / закрыть от лица HR), база знаний (тестовый вопрос к RAG), состояние сервисов, просмотр Postgres / Mongo / Redis / Kafka / S3.

> Админка — только для тестирования: показывает персональные данные и даёт полный доступ к базам. После проверки выключить: `docker compose --profile admin down` и `ADMIN_ACCESS=off`.

## 8. Тесты

```bash
cd bot && npm test                 # расписание, загрузчик и валидатор сценария
cd bot && npm run test:int         # интеграционные: нужны Mongo и Redis (MONGO_URL, REDIS_URL);
                                   # сотрудник проходит 3 месяца на поддельных часах
docker compose run --rm --no-deps ml python -m unittest discover -s tests -v   # ML
```

## 9. Обновление и сброс

- После правок кода: `docker compose up -d --build bot` (или `ml ml-mood-consumer`, `admin`). Миграции БД применять **до** пересборки бота.
- Сброс всех данных: `docker compose down -v` (init-скрипты выполнятся заново, придётся повторить шаги 3 и 4).
- Логи: `docker compose logs -f bot ml`.

## 10. Если что-то не работает

| Симптом | Причина / что делать |
|---------|----------------------|
| «Сервис ответов временно недоступен» | ML вернул ошибку — `docker compose logs ml` (пустая база, не скачана модель, таймаут, нет `ollama`) |
| `/v1/ask` → 503 «Векторная база пуста» | не выполнен шаг 4 |
| `mongo` не стартует, «known incompatibility» | образ Mongo должен быть 7.0 (`mongo:7.0.41`), не 8.x; том от 8.x удалить |
| `ml` долго `unhealthy` | идёт первая загрузка модели эмбеддингов |
| Активация по QR падает | не применена миграция `003_users_hr.sql` на БД, созданной до неё |
| У сотрудника «нет закреплённого HR» | сотрудник заведён до миграции `003`; пересоздать приглашение или проставить `users.hr_id` |
| `curl localhost:8000` отдаёт 503 | задан `http_proxy`: использовать `curl --noproxy '*'` |
